# Data Science Jobs Radar

Бот, который парсит вакансии, отбирает целевые роли в data science / ml
по заданным сферам (healthtech, fintech, edtech и т.д.) и присылает новые вакансии каждые 4 часа (если они есть). Каждый подписчик настраивает свой набор сфер и ролей через кнопки в боте.
Пример сбора вакансий за неделю: всего 324 вакансии → 319 после дедупликации → 5 попадает под DS-роли.

## Как это устроено

В корне репозитория лежат:

- `main.py` — оркестрация всего пайплайна + расписание запусков;
- `collect_history.py` — разовый скрипт: наполняет архив статистики вакансиями за месяц;
- `setup.sh` — скрипт первичного развертывания бота на сервере;
- `update.sh` — скрипт обновления уже задеплоенного бота (git pull + restart);
- `requirements.txt` — зависимости проекта;
- `pyproject.toml` — конфигурация линтера (ruff);
- `LICENSE` — лицензия MIT.

Логика проекта разложена по трём папкам:

- `sources/` — парсинг отдельных job-бордов;
- `pipeline/` — общая обработка вакансий (нормализация, дедупликация, классификация, статистика);
- `bot/` — телеграм-бот (команды, подписчики, доставка сводок).

### Источники (`sources/`)

- **geekjob** — html-парсинг листинга + карточки вакансии (`geekjob.py`).
- **getmatch** — внутренний json api (`getmatch.py`).
- **hirify** — html-парсинг листинга + карточки вакансии (`hirify.py`), фильтр по `remote_type=russia`.
- **datasecrets** — html-парсинг листинга + карточки вакансии (`datasecrets.py`).
  Одна страница со всеми вакансиями, дат публикации на сайте нет, поэтому
  в `published_at` пишется дата первой встречи вакансии
  (`data/datasecrets_seen.json`).

Каждый источник отдает список словарей с одинаковым набором полей
(`title`, `company`, `location`, `work_format`, `salary_min/max`,
`currency`, `salary_period`, `published_at`, `url`, `description`,
`skills`, `source`, `level`), чтобы дальше по пайплайну было не важно,
откуда пришла вакансия. Общие для источников операции (поиск ключевых
слов, ролей по таксономии, грубая оценка грейда, очистка html) вынесены
в `parsing.py`.

### Пайплайн (`pipeline/`)

- `parsing.py` — общие функции поиска: ключевые слова, роли, грейд, strip html.
- `normalize.py` — приведение полей к единому виду (текст, зп, локация, формат работы).
  Приводит текстовые поля к нижнему регистру и убирает лишние пробелы
  (это важно для матчинга ключевых слов в `classify.py`), а также
  нормализует локацию, формат работы и типы зарплатных/датных полей.
- `dedupe.py` — удаление дублей: сначала точные по `url`, затем внутри
  одной компании — похожие по совпадению/вхождению title, оставляя
  наиболее полную версию (с зарплатой, описанием и списком навыков).
- `keywords.py` — таксономии: сферы, роли, грейды, скиллы, исключенные роли.
- `classify.py` — разметка: целевая роль / сфера / исключенные роли.

  Вакансия попадает в сводку (`is_target = True`), если одновременно:

  1. в названии нашлась целевая роль (`ROLE_TAXONOMY` — data scientist,
     ml/ai-ml engineer, nlp/cv engineer, data analyst/engineer,
     data governance/quality, research scientist и т.д.);
  2. роль не входит в список исключённых (`EXCLUDED_ROLES` — frontend,
     backend, devops, qa и т.д.);
  3. в тексте вакансии (title + description + specialization + industry +
     skills) нашлось хотя бы одно ключевое слово хотя бы одной сферы из
     `TARGET_KEYWORDS` (healthtech, medtech, femtech, fintech, edtech,
     hrtech, adtech, gamedev, logistics, ecommerce).

  Для каждой сферы из `TARGET_KEYWORDS` в вакансию добавляется отдельная
  колонка со списком найденных ключевых слов — по ней `summary.py`
  фильтрует вакансии для конкретного подписчика.

- `stats.py` / собранная логика статистики:
  - собирает отдельный архив целевых вакансий
    (`data/vacancies_stats.pkl`), не зависящий от истории рассылок;
  - зарплата в архиве приводится к единому виду: период (`year`/`hour`)
    пересчитывается в месяц, а сумма конвертируется в рубли по курсу ЦБ РФ;
  - `top_skills` / `build_top_skills_message` считают топ-N навыков по
    архиву с учетом фильтров подписчика (сферы/роли) — это то, что
    отдаётся по кнопке «📊 Топ навыков» / команде `/top_skills`.
- `summary.py` — сборка текста сводки + фильтрация по сферам/ролям.

### Телеграм-бот (`bot/`)

- `telegram_api.py` — низкоуровневые вызовы Telegram Bot API.
- `subscribers.py` — хранение подписчиков и их фильтров (сферы/роли)
  в `data/subscribers.json`.
- `keyboards.py` — inline-клавиатуры для выбора сфер и ролей.
- `history.py` — история отправленных вакансий по каждому подписчику
  в `data/sent_vacancies.json`.
- `telegram_bot.py` — обработка команд/кнопок, рассылка сводок.

Логика работы:

- `/start` — подписка на рассылку (по умолчанию без фильтров — все
  сферы и роли), `/stop` — отписка.
- Кнопки «🎯 Выбрать сферы» и «🧩 Выбрать роли» (или команды
  `/industries`, `/roles`) открывают inline-клавиатуру, где можно
  тоглить нужные пункты и подтвердить выбор кнопкой «✅ Показать
  вакансии».
- Кнопка «📊 Топ навыков» (или команда `/top_skills`) показывает топ-5
  навыков по архиву `vacancies_stats.pkl` с учётом текущих фильтров
  подписчика.
- При любом изменении фильтров для подписчика сбрасывается
  персональная история отправленных вакансий, чтобы под новый фильтр
  он снова увидел весь актуальный пул.
- Рассылка сводки (`send_summary`) и подтверждение через кнопку
  «Показать вакансии» используют общую функцию доставки
  `_deliver_vacancies`, которая берет неотправленные подписчику
  вакансии, фильтрует их по его сферам/ролям и отправляет сообщения.
- Опрос новых сообщений (`poll_updates`) идет отдельной джобой каждые
  15 секунд, независимо от джобы со сводкой.

### Расписание запусков (`main.py`)

- при первом запуске в сводку идут все вакансии за последние 7 дней;
- при каждом следующем запуске источники также фетчатся за 7 дней, а
  какие из них новые — определяется персонально для каждого
  подписчика по `data/sent_vacancies.json`;
- параллельно с классификацией каждый прогон дописывает новые целевые
  вакансии в архив статистики (`data/vacancies_stats.pkl`);
- джоба со сводкой запускается каждые 4 часа, джоба опроса Telegram —
  каждые 15 секунд.

## Как запустить

1. Установить зависимости: `pip install -r requirements.txt`.
2. Создать `.env` в корне проекта:

   ```
   TELEGRAM_BOT_TOKEN=токен_бота_от_botfather
   ```

3. Запустить:

   ```
   python main.py
   ```

   Первый прогон пайплайна выполнится сразу, дальше — по расписанию.
   
## Деплой на сервер (`setup.sh`)

Скрипт `setup.sh` разворачивает бота на чистом Ubuntu-сервере без
ручных шагов:

1. обновляет систему и ставит системные пакеты (`python3-venv`,
   `python3-pip`, `git`, `ufw`);
2. создает отдельного непривилегированного пользователя `botuser`,
   от имени которого работает бот;
3. клонирует репозиторий в `/home/botuser` (либо делает `git pull`,
   если папка уже есть);
4. создает виртуальное окружение и ставит зависимости из
   `requirements.txt`;
5. создает папку `data/` с правильным владельцем;
6. запрашивает токен бота и кладёт его в `.env` с правами `600`
   (читать может только `botuser`);
7. создаёт systemd-юнит `data-science-jobs-radar.service`
   (`Restart=on-failure`, автозапуск при перезагрузке) и запускает его;
8. включает `ufw` с разрешенным `OpenSSH`.

Обновление уже задеплоенного бота (`update.sh`)

Для выкатки новых изменений на уже настроенный сервер не нужно повторно проходить весь `setup.sh`, используется более легкий `update.sh`:

1. подтягивает изменения из git (git pull от имени botuser);
2. переустанавливает зависимости из requirements.txt в существующем venv (на случай, если они поменялись);
3. перезапускает systemd-службу data-science-jobs-radar.

Запуск (от root, на самом сервере):

 ```
bash setup.sh
 ```

Дальше управлять сервисом можно стандартными командами:

 ```
systemctl status data-science-jobs-radar
systemctl restart data-science-jobs-radar
journalctl -u data-science-jobs-radar -f
 ```

## Данные

Все промежуточные и служебные файлы лежат в `data/` (создается
автоматически, в git не коммитится):

- `vacancies_raw.csv` — сырые вакансии до нормализации и дедупликации;
- `vacancies_classify.csv` — вакансии после классификации;
- `vacancies_latest.pkl` — общий (не персональный) снэпшот целевых
  вакансий последнего прогона, используется ботом при подтверждении
  фильтра;
- `subscribers.json` — подписчики и их фильтры (сферы/роли);
- `sent_vacancies.json` — какие url и когда были отправлены каждому
  подписчику (используется, чтобы не слать повторно);
- `telegram_offset.txt` — offset последнего обработанного апдейта Telegram;
- `datasecrets_seen.json` — когда каждая вакансия datasecrets впервые попала
  в выдачу (заменяет отсутствующую на сайте дату публикации).
