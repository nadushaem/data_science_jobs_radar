# Data Science Jobs Radar

![ci](https://github.com/nadushaem/data_science_jobs_radar/actions/workflows/ci.yml/badge.svg)

Телеграм-бот, который парсит вакансии с нескольких job-бордов, отбирает целевые
роли в data science / ml по заданным сферам (healthtech, fintech, edtech и т.д.)
и присылает новые вакансии каждые 4 часа (если они есть). Каждый подписчик
настраивает свой набор сфер и ролей через кнопки в боте.

Пример сбора вакансий за неделю: всего 324 вакансии → 319 после дедупликации →
5 попадает под DS-роли.

## Как это устроено

В корне репозитория лежат:

- `main.py` — оркестрация всего пайплайна + расписание запусков;
- `collect_history.py` — разовый скрипт: наполняет архив статистики вакансиями за месяц;
- `setup.sh` — первичное развертывание бота на сервере;
- `update.sh` — обновление уже задеплоенного бота (git pull + restart);
- `requirements.txt` — зависимости проекта;
- `requirements-dev.txt` — зависимости для разработки (pytest, pre-commit);
- `pyproject.toml` — конфигурация ruff и pytest;
- `.pre-commit-config.yaml` — хуки, которые запускаются перед коммитом;
- `.github/workflows/ci.yml` — CI в GitHub Actions;
- `LICENSE` — лицензия MIT.

Логика проекта разложена по папкам:

- `sources/` — парсинг отдельных job-бордов;
- `pipeline/` — общая обработка вакансий (нормализация, дедупликация, классификация, статистика);
- `bot/` — телеграм-бот (команды, подписчики, доставка сводок);
- `tests/` — unit-тесты.

### Источники (`sources/`)

- **geekjob** — html-парсинг листинга + карточки вакансии (`geekjob.py`).
- **getmatch** — внутренний json api (`getmatch.py`). Если зарплата скрыта,
  она достается из текстового `salary_description`.
- **hirify** — html-парсинг листинга + карточки вакансии (`hirify.py`),
  фильтр по `remote_type=russia`, обработка 429 с учетом `Retry-After`.
- **datasecrets** — html-парсинг листинга + карточки вакансии (`datasecrets.py`).
  Это одна страница со всеми вакансиями, дат публикации на сайте нет. Поэтому
  в `published_at` пишется дата первой встречи вакансии
  (`data/datasecrets_seen.json`).

Каждый источник отдает список словарей с одинаковым набором полей
(`title`, `company`, `location`, `work_format`, `salary_min/max`,
`currency`, `salary_period`, `published_at`, `url`, `description`,
`skills`, `source`, `level`). Благодаря этому дальше по пайплайну не важно,
откуда пришла вакансия. Зарплату и дату каждый источник парсит сам. Общие
для источников операции (поиск ключевых слов и ролей по таксономии, грубая
оценка грейда, парсинг зарплаты, очистка html) вынесены в `pipeline/parsing.py`.

Если источник падает, это не роняет весь прогон: ошибка печатается,
и пайплайн идет дальше с остальными источниками.

### Пайплайн (`pipeline/`)

- `parsing.py` — общие функции: поиск ключевых слов и ролей (по границам слов,
  `ai / ml` == `ai/ml`), оценка грейда, парсинг зарплаты, strip html.
- `normalize.py` — приведение общих полей к единому виду: текст в нижний
  регистр без лишних пробелов (важно для матчинга в `classify.py`),
  нормализация локации (`мск` → `москва`) и формата работы
  (`remote` / `hybrid` / `onsite`), приведение типов зарплатных и датных полей.
- `dedupe.py` — удаление дублей: сначала точные по `url`, затем внутри
  одной компании — похожие по совпадению/вхождению title. Остается
  наиболее полная версия (с зарплатой, описанием и списком навыков).
- `keywords.py` — таксономии: сферы, роли, грейды, скиллы, исключенные роли.
- `classify.py` — разметка: целевая роль / сфера / исключенные роли.

  Вакансия попадает в сводку (`is_target = True`), если одновременно:

  1. в названии нашлась целевая роль (`ROLE_TAXONOMY` — data scientist,
     ml / ai-ml engineer, nlp / cv engineer, mlops engineer,
     data analyst / engineer, data governance / quality, research scientist);
  2. роль не входит в список исключенных (`EXCLUDED_ROLES` — frontend,
     backend, devops, qa и т.д.);
  3. в тексте вакансии (title + company + description + specialization +
     industry + skills) нашлось хотя бы одно ключевое слово хотя бы одной
     сферы из `TARGET_KEYWORDS` (healthtech, medtech, femtech, fintech,
     edtech, hrtech, adtech, gamedev, logistics, ecommerce, telecom, media).

  Для каждой сферы в вакансию добавляется отдельная колонка со списком
  найденных ключевых слов. По ней `summary.py` фильтрует вакансии для
  конкретного подписчика.

- `stats.py` — статистика:
  - собирает отдельный архив целевых вакансий (`data/vacancies_stats.pkl`),
    не зависящий от истории рассылок;
  - приводит зарплату в архиве к единому виду: период (`year` / `hour`)
    пересчитывается в месяц, сумма конвертируется в рубли по курсу ЦБ РФ
    (при недоступности ЦБ используются запасные курсы `FALLBACK_RATES`);
  - `top_skills` / `build_top_skills_message` считают топ-N навыков по
    архиву с учетом фильтров подписчика (сферы / роли).
- `summary.py` — фильтрация вакансий по сферам / ролям и сборка текста
  сводки с разбиением на сообщения под лимит Telegram.

### Телеграм-бот (`bot/`)

- `api.py` — низкоуровневые вызовы Telegram Bot API (`getUpdates`,
  `sendMessage`, `editMessageReplyMarkup`, `answerCallbackQuery`, `deleteWebhook`).
- `handlers.py` — обработка команд и кнопок, рассылка сводок, цикл опроса.
- `keyboards.py` — основная клавиатура и inline-клавиатуры выбора сфер и ролей.
- `subscribers.py` — хранение подписчиков и их фильтров в `data/subscribers.json`.
- `history.py` — персональная история отправленных вакансий в
  `data/sent_vacancies.json` (записи старше 30 дней вычищаются).

Команды и кнопки:

| Кнопка | Команда | Что делает |
|---|---|---|
| — | `/start` | подписка на рассылку (по умолчанию все сферы и роли) |
| 🎯 Выбрать сферы | `/industries` | inline-выбор сфер |
| 🧩 Выбрать роли | `/roles` | inline-выбор ролей |
| 📊 Топ навыков | `/top_skills` | топ-5 навыков по архиву с учетом фильтров |
| 👀 Посмотреть вакансии | `/view_all` | все актуальные вакансии за неделю по фильтрам |
| 🚫 Отказаться от рассылки | `/stop` | отписка |

Логика работы:

- в inline-клавиатуре пункты тоглятся, «♻️ Сбросить» очищает выбор,
  «✅ Показать вакансии» сразу присылает подходящие вакансии;
- при любом изменении фильтров сбрасывается персональная история
  отправленных вакансий, чтобы под новый фильтр подписчик снова увидел
  весь актуальный пул;
- плановая рассылка (`send_summary`) и кнопка «Показать вакансии»
  используют общую функцию `_deliver_vacancies`: она берет неотправленные
  подписчику вакансии, фильтрует их по его сферам / ролям и отправляет;
- опрос новых сообщений (`poll_updates`) идет отдельной джобой каждые
  15 секунд, независимо от джобы со сводкой.

### Расписание запусков (`main.py`)

- при старте удаляется webhook (бот работает через long polling),
  и пайплайн сразу прогоняется один раз;
- при каждом запуске источники фетчатся за 7 дней, а какие вакансии
  новые, определяется персонально для каждого подписчика по
  `data/sent_vacancies.json`;
- каждый прогон дописывает новые целевые вакансии в архив статистики;
- джоба со сводкой запускается каждые 4 часа, джоба опроса Telegram —
  каждые 15 секунд.

## Как запустить

Нужен Python 3.12+.

1. Установить зависимости: `pip install -r requirements.txt`.
2. Создать `.env` в корне проекта:

```
   TELEGRAM_BOT_TOKEN=токен_бота_от_botfather
```

3. (опционально) наполнить архив статистики вакансиями за месяц:

```
   python collect_history.py
```

4. Запустить бота:

```
   python main.py
```

   Первый прогон пайплайна выполнится сразу, дальше — по расписанию.

## Деплой на сервер

### Первичная настройка (`setup.sh`)

Скрипт разворачивает бота на чистом Ubuntu-сервере без ручных шагов:

1. обновляет систему и ставит системные пакеты (`python3-venv`,
   `python3-pip`, `git`, `ufw`);
2. создает отдельного непривилегированного пользователя `botuser`,
   от имени которого работает бот;
3. клонирует репозиторий в `/home/botuser` (или делает `git pull`,
   если папка уже есть);
4. создает виртуальное окружение и ставит зависимости из `requirements.txt`;
5. создает папку `data/` с правильным владельцем;
6. запрашивает токен бота и кладет его в `.env` с правами `600`
   (читать может только `botuser`);
7. создает systemd-юнит `data-science-jobs-radar.service`
   (`Restart=on-failure`, автозапуск при перезагрузке) и запускает его;
8. включает `ufw` с разрешенным `OpenSSH`.

Запуск (от root, на самом сервере):

```
bash setup.sh
```

### Обновление (`update.sh`)

Для выкатки новых изменений не нужно повторно проходить весь `setup.sh`:

1. подтягивает изменения из git (от имени `botuser`);
2. переустанавливает зависимости в существующем venv;
3. перезапускает systemd-службу.

```
bash update.sh
```

### Управление сервисом

```
systemctl status data-science-jobs-radar
systemctl restart data-science-jobs-radar
journalctl -u data-science-jobs-radar -f
```

## Разработка

```
pip install -r requirements-dev.txt
pre-commit install
```

**Pre-commit.** Перед каждым коммитом автоматически запускаются ruff
(линтер + форматтер), базовые проверки файлов (yaml / toml, конфликты
мерджа, приватные ключи, забытые `breakpoint()`, файлы больше 500 кб)
и запрет на коммит `.env` / `data/`. Прогнать вручную по всему
репозиторию: `pre-commit run --all-files`.

**Тесты.** Unit-тесты лежат в `tests/` и работают без сети
(`requests` подменяется через `monkeypatch`, время замораживается
фикстурой `freeze_now`). Покрыты:

- `pipeline`: parsing, normalize, dedupe, classify, summary, stats;
- `bot`: история отправленных вакансий;
- `sources`: разбор дат (geekjob, hirify) и зарплат (getmatch).

Запуск:

```
pytest
```

**CI.** GitHub Actions на каждый push и pull request прогоняет
pre-commit по всему репозиторию.

## Данные

Все промежуточные и служебные файлы лежат в `data/` (создается
автоматически, в git не коммитится):

- `vacancies_raw.csv` — сырые вакансии до нормализации и дедупликации;
- `vacancies_classify.csv` — вакансии после классификации;
- `vacancies_latest.pkl` — общий (не персональный) снэпшот целевых
  вакансий последнего прогона, используется ботом для «Показать вакансии»
  и «Посмотреть вакансии»;
- `vacancies_stats.pkl` — архив целевых вакансий для статистики;
- `subscribers.json` — подписчики и их фильтры (сферы / роли);
- `sent_vacancies.json` — какие url и когда были отправлены каждому
  подписчику;
- `telegram_offset.txt` — offset последнего обработанного апдейта Telegram;
- `datasecrets_seen.json` — когда каждая вакансия datasecrets впервые
  попала в выдачу.
