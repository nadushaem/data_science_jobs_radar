# Healthtech Jobs Radar

Бот, который парсит вакансии, отбирает те, что относятся
к data science / ml в healthtech / medtech / femtech (плюс временно
e-commerce для обкатки пайплайна), и раз в 4 часа присылает сводку
в Telegram.

## Как это устроено

```
sources/*              → сырые вакансии с job-бордов
normalize.py           → приведение полей к единому виду (текст, зп, локация)
dedupe.py              → удаление дублей (по url и по похожести title+company)
classify.py            → разметка: целевая роль / сфера / исключенные роли
summary.py             → сборка текста сводки для Telegram
telegram_bot.py        → рассылка подписчикам, подписка/отписка
main.py                → оркестрация всего пайплайна + расписание запусков
```

### Источники (`sources/`)

- **geekjob** — html-парсинг листинга + карточки вакансии (`geekjob.py`).
- **getmatch** — внутренний json api (`getmatch.py`).

Каждый источник отдает список словарей с одинаковым набором полей
(`title`, `company`, `location`, `work_format`, `salary_min/max`,
`currency`, `salary_period`, `published_at`, `url`, `description`,
`skills`, `source`, `level`), чтобы дальше по пайплайну было не важно,
откуда пришла вакансия.

### Нормализация и дедупликация

`normalize.py` приводит текстовые поля к нижнему регистру и убирает
лишние пробелы (это важно для матчинга ключевых слов в `classify.py`),
а также нормализует локацию, формат работы и типы зарплатных полей.

`dedupe.py` сначала убирает точные дубли по `url`, затем ищет похожие
вакансии внутри одной компании (по совпадению/вхождению title) и
оставляет наиболее полную версию — с зарплатой, описанием и списком
навыков.

### Классификация (`classify.py`, `keywords.py`)

Вакансия попадает в сводку (`is_target = True`), если одновременно:

1. в названии нашлась целевая роль (`ROLE_TAXONOMY` — data scientist,
   ml engineer, nlp engineer и т.д.);
2. роль не входит в список исключённых (`EXCLUDED_ROLES` — frontend,
   qa, devops и т.д.);
3. в тексте вакансии (title + description + specialization + industry +
   skills) нашлось хотя бы одно ключевое слово из `TARGET_KEYWORDS`
   (healthtech, medtech, femtech, e-commerce).

### Telegram-бот (`telegram_bot.py`)

- `/start` — подписка на рассылку, `/stop` — отписка. Список подписчиков
  хранится в `data/subscribers.json`.
- Опрос новых сообщений (`poll_updates`) идет отдельной джобой каждые
  15 секунд, независимо от джобы со сводкой.

### Расписание запусков (`main.py`)

- при первом запуске (нет файла `data/last_run.txt`) в сводку идут все
  вакансии за последние 7 дней;
- при каждом следующем запуске — только вакансии, опубликованные после
  прошлого успешного запуска (метка обновляется только если рассылка
  прошла без ошибок, иначе следующий запуск подхватит пропущенное);
- джоба со сводкой запускается каждые 4 часа, джоба опроса Telegram —
  каждые 15 секунд.

## Как запустить

1. Установить зависимости: `pip install -r requirements.txt`.
2. Создать `.env` в корне проекта:

   ```
   TELEGRAM_BOT_TOKEN=токен_бота_от_botfather
   ```

3. Запустить:

   ```
   python main.py
   ```

   Первый прогон пайплайна выполнится сразу, дальше — по расписанию.

## Данные

Все промежуточные и служебные файлы лежат в `data/` (создается
автоматически, в git не коммитится):

- `vacancies_raw.csv` — сырые вакансии до нормализации и дедупликации;
- `vacancies_classify.csv` — вакансии после классификации (последний прогон);
- `subscribers.json` — список подписчиков Telegram.

- Разбивка зарплатной статистики по грейдам и ролям отдельно;
- Топ навыков среди целевых вакансий;
- Выбор ролей в DS и сфер помимо медицины;
- Поставить на сервер для обеспечения автономной работы.
