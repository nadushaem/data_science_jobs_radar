# Правила разметки gold set (v1)

Цель: для каждой вакансии зафиксировать, должна ли она попадать в сводку бота,
независимо от того, что находит классификатор.

## Процесс

- размечаем по заголовку; если заголовок неоднозначный — читаем описание
- предсказания пайплайна при разметке не смотрим
- `industries` заполняем только при `ds_role = 1`
- сомневаешься → ставишь `unsure = 1` и пишешь причину в `comment`,
  такие строки считаем в метриках отдельно

## ds_role: целевая роль (1 / 0)

Смотрим, чем человек будет заниматься, а не только на слова в заголовке.

**1**, если основная работа — модели, данные или аналитика данных:
data scientist, ml / ai engineer, ai engineer (llm-приложения, rag, агенты),
nlp / cv engineer, research scientist, mlops, data engineer (в т.ч. dwh / etl),
data analyst / аналитик данных, data governance / quality.
Руководящие позиции в этих направлениях (lead, head of data science) — тоже 1.

**0**: backend / frontend / mobile / devops / qa, даже если в описании есть ml;
продакт-менеджеры, контент-менеджеры, маркетинг с «ai» в названии;
системные, бизнес-, 1с-аналитики.

**Пограничные — решение зафиксировано здесь:**
- product analyst → 0
- bi-аналитик → 0
- fullstack analyst → 0
- database engineer → 0
- разметчик данных → 1, data quality
- rl_engineer → 1, research scientist + ai_engineer / dl_engineer / ml-engineer (смотреть по описанию)
- «архитектор ...» → внимательно смотреть описание вакансии, может быть как 1, так и 0
- «python-разработчик», если по описанию основная работа — обучение моделей → 1

## roles: канонические роли (только при ds_role = 1)

Ключи из `ROLE_TAXONOMY`, несколько через `|`: `ml_engineer|data_scientist`.
DS-роль, не подходящая ни под один ключ → `other`.

## industries: сферы (только при ds_role = 1)

Ключи из `TARGET_KEYWORDS`, несколько через `|`. Пусто — если сфера не из списка.

Главный принцип: **сфера — это бизнес работодателя или конкретного продукта,
на который нанимают**, а не упоминания в тексте.

- банк, страховая, брокер, платежный сервис → `fintech`
- экосистемы (яндекс, vk, сбер, озон): сфера конкретного подразделения, если
  оно названо (яндекс маркет → `ecommerce`, озон банк → `fintech`, vk без уточнения → `it`); IT-подразделение сбера → `it`
- интеграторы, аутсорс, кадровые агентства: сфера проекта, если она явно
  указана («проект для крупного банка» → `fintech`»), иначе пусто
- MAGNIT TECH, X5 Tech → `ecommerce`
- **не считается сферой**: список клиентов («работаем с банками и ритейлом»),
  требования к опыту («опыт в финтехе — плюс»), примеры задач
- компания скрыта, но сфера указана в скобках → по скобкам

## industry_other: сфера вне списка (свободный текст)

Заполняем, если `ds_role = 1`, а сферы нет в `TARGET_KEYWORDS`. По этому полю видно, какие сферы стоит завести
следующими (так появились govtech / traveltech / cybersecurity).

## Формат файла `eval/gold_v1.csv`

Одна строка — одна вакансия снапшота `data/eval/snapshot_v1.pkl`.
Описаний в файле нет, связь с текстами вакансий — по `url`.

| Колонка | Значения | Пример |
|---|---|---|
| `url` | ключ для связи со снапшотом | `https://getmatch.ru/vacancies/...` |
| `ds_role` | `1` / `0` | `1` |
| `roles` | ключи через `\|` или пусто | `ml_engineer\|data_scientist` |
| `industries` | ключи через `\|` или пусто | `fintech` |
| `industry_other` | свободный текст | `карты / геосервисы` |
| `unsure` | `1` / `0` | `0` |
| `comment` | свободный текст | `интегратор, проект не указан` |

`is_target` не размечается: он выводится как `ds_role = 1` и непустые
`industries`, так же как в `pipeline/classify.py`.


# Дедупликация: `eval/dedupe_gold_v1.csv`

Одна строка — пара вакансий одной компании из снапшота `data/eval/dedupe_snapshot_v1.pkl`.
В разметку попадают кандидаты: похожие названия, одинаковая «голова» названия
или общий текст ≥ 0.5. Размечаем вслепую: что склеил пайплайн, не смотрим.

**1** — одна и та же позиция в одной команде. Борд переписал название, добавил тег
в скобках («(fintech)», «(ai)»), грейд или пересказал описание — всё равно 1.

**0** — разные команды или продукты, разный стек, явно разный грейд, разные города.

**Пограничные — решение зафиксировано здесь:**
- одинаковое название на одном борде — не повод ставить 1, открываем обе ссылки:
  три «middle support engineer» отп банка на getmatch — три разные команды
- одна роль в разных городах (москва / новосибирск) → 0, даже при похожем тексте
- один id вакансии с разным slug в url (getmatch сменил название) → 1
- непонятно даже по ссылкам → `unsure = 1`, в метрики не идёт

| Колонка | Значения |
|---|---|
| `company` | ключ компании, как его видит дедуп |
| `source_*`, `title_*`, `url_*` | обе вакансии пары |
| `is_dup` | `1` / `0` |
| `unsure` | `1` или пусто |
| `comment` | откуда метка, если она не очевидна по названиям |
