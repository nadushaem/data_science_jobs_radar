# Правила разметки gold set (v1)

Цель: для каждой вакансии зафиксировать, должна ли она попадать в сводку бота,
независимо от того, что находит классификатор.

## Процесс

- размечаем по заголовку; если заголовок неоднозначный — читаем описание
- предсказания пайплайна при разметке не смотрим
- `industries` заполняем только при `ds_role = 1`
- сомневаешься → ставишь `unsure = 1` и пишешь причину в `comment`,
  такие строки считаем в метриках отдельно

## ds_role: целевая роль (1 / 0)

Смотрим, чем человек будет заниматься, а не только на слова в заголовке.

**1**, если основная работа — модели, данные или аналитика данных:
data scientist, ml / ai-ml engineer, ai engineer (llm-приложения, rag, агенты),
nlp / cv engineer, research scientist, mlops, data engineer (в т.ч. dwh / etl),
data analyst / аналитик данных, data governance / quality.
Руководящие позиции в этих направлениях (lead, head of data science) — тоже 1.

**0**: backend / frontend / mobile / devops / qa, даже если в описании есть ml;
продакт-менеджеры, контент-менеджеры, маркетинг с «ai» в названии;
системные, бизнес-, 1с-аналитики; разметчики данных.

**Пограничные — решение зафиксировано здесь:**
- product analyst → 0
- bi-аналитик → 0
- «python-разработчик», если по описанию основная работа — обучение моделей → 1

## roles: канонические роли (только при ds_role = 1)

Ключи из `ROLE_TAXONOMY`, несколько через `|`: `ml_engineer|data_scientist`.
ai engineer → `ai_ml_engineer`. DS-роль, не подходящая ни под один ключ → `other`.

## industries: сферы (только при ds_role = 1)

Ключи из `TARGET_KEYWORDS`, несколько через `|`. Пусто — если сфера не из списка.

Главный принцип: **сфера — это бизнес работодателя или конкретного продукта,
на который нанимают**, а не упоминания в тексте.

- банк, страховая, брокер, платежный сервис → `fintech`
- экосистемы (яндекс, vk, сбер, озон): сфера конкретного подразделения, если
  оно названо (яндекс маркет → `ecommerce`, озон банк → `fintech`);
  не названо → пусто. исключение: сбер без уточнения → `fintech`
- интеграторы, аутсорс, кадровые агентства: сфера проекта, если она явно
  указана («проект для крупного банка» → `fintech»), иначе пусто
- **не считается сферой**: список клиентов («работаем с банками и ритейлом»),
  требования к опыту («опыт в финтехе — плюс»), примеры задач
- компания скрыта, но сфера указана в скобках → по скобкам

## industry_other: сфера вне списка (свободный текст)

Заполняем, если `ds_role = 1`, а сферы нет в `TARGET_KEYWORDS`: «карты / геосервисы»,
«железо», «it-интегратор». По этому полю видно, какие сферы стоит завести
следующими (так появились govtech / traveltech / cybersecurity).
