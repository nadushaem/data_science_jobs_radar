# Оценка качества

Отбор вакансий и дедупликация работают на правилах, поэтому качество проверяется
на ручной разметке, а не по ощущениям от сводки. Правила разметки и решения
по пограничным случаям — в [`LABELING.md`](LABELING.md).

## Методология

- **dev / test.** Разметка v1 — dev: по ее ошибкам дорабатывались правила,
  поэтому метрики на ней оптимистичны. Версия после доработки фиксируется тегом.
  Финальные метрики считаются на v2 — следующей неделе, размеченной без взгляда
  на предсказания.
- **Интервалы.** 95% bootstrap, версии сравниваются на одних и тех же ресемплах.
- **Версии.** `--rev` подставляет правила из любой ревизии git, так что любую
  версию можно оценить на любой разметке.
- **Данные.** Снапшоты вакансий лежат в `data/eval/` и в git не попадают,
  разметка связана с ними по `url`.

## Отбор DS-ролей — `evaluate.py`

`gold_v1.csv`: 374 вакансии за неделю в конце сентября 2026, из них 80 с DS-ролью.

| Версия | Precision | Recall [95% ДИ] | F1 |
|---|---|---|---|
| наивный baseline (data / ml / ai в названии) | 0.80 | 0.71 [0.62, 0.81] | 0.75 |
| до разбора ошибок (`528b8b8`) | 0.98 | 0.75 [0.65, 0.84] | 0.85 |
| `taxonomy-dev-v1` | 1.00 | 0.90 [0.83, 0.96] | 0.95 |

Что нашел разбор ошибок:

- около 14% DS-вакансий не попадали ни в одну сферу — так появилась сфера IT / Bigtech;
- продукты экосистем уходили в сферу материнской компании (GigaChat по слову
  «сбер» → fintech) — добавлены исключения для подразделений;
- не хватало алиасов для RL / LLM / applied scientist и руководящих ролей.

## Дедупликация — `evaluate_dedupe.py`

`dedupe_gold_v1.csv`: 232 пары вакансий одной компании за неделю в начале октября
2026 — 72 дубля, 159 разных вакансий, 1 спорная. Метрики считаются по парам,
отдельно для пар с разных бордов и с одного.

| Версия | Precision | Recall [95% ДИ] | F1 |
|---|---|---|---|
| наивный baseline (одинаковые названия) | 0.90 | 0.38 [0.27, 0.49] | 0.53 |
| похожесть названий (`a91cc6f`) | 0.72 | 0.61 [0.50, 0.72] | 0.66 |
| + общий текст описаний (`dedupe-by-description`) | 0.79 | 0.51 [0.39, 0.64] | 0.62 |
| `dedupe-dev-v1` | 0.98 | 0.90 [0.83, 0.97] | 0.94 |

Что нашел разбор ошибок:

- hirify дописывает к названию отрасль в скобках и пересказывает описание:
  у настоящих дублей общего текста почти нет, и порог по тексту разрывал их;
- на одном борде одинаковое название часто означает разные вакансии
  (разные команды, города) — там нужен общий текст;
- одна компания записана разными алфавитами: «Яндекс» / «Yandex»,
  латинская «A» в «Альфа».

Recall считается среди пар-кандидатов: похожие названия или общий текст.

## Запуск

```
python -m eval.evaluate                              # отбор, рабочая копия
python -m eval.evaluate --rev taxonomy-dev-v1        # зафиксированная версия
python -m eval.evaluate_dedupe --rev dedupe-dev-v1   # дедупликация
```

Снапшот для дедупа снимается один раз с копии серверной базы:
`python -m eval.evaluate_dedupe --freeze` с `DB_PATH`, указывающим на копию.
Ошибки последнего прогона сохраняются в `data/eval/` для разбора.
